# Иконки предметов The Escapists 1 — РАСШИФРОВАНО

> Раньше это было главным нерешённым местом (см. `MODDING_THE_ESCAPISTS.md` §0 и §4:
> «иконка привязана к ID», «пока не полезешь в exe, любой новый ID будет без своей картинки»).
> Теперь чанки с анимациями объектов **расшифрованы**, и соответствие
> **«ID предмета → кадр/хендл иконки» установлено точно** (проверено визуально).

## Что сделано

1. **`te_crypto.py`** — точный порт нативного дешифровщика чанков Fusion 2.5
   (`CTFAK-Native/encryption.cpp` + `wrapper.cpp make_key`). Проверен байт-в-байт
   против скомпилированного C++: ключевой поток `191b840cc64e03db...`.
   Работает для чанков с `flag=3` (compressed+encrypted): `GlobalValues`, `GlobalStrings`,
   `Serial`, `FrameHandles` и — главное — **подчанки `FrameItems` (8745)**
   (`Object Info Header` 17476 / `Object Common` 17478).
   Ключ: `md5-подобный MakeKey(title, copyright, editorFilename, magic_char=54)`,
   строки — `The Escapists` + `2016 Mouldy Toof Studios / Team17 Digital` +
   `C:\Users\Chris\Desktop\Game Projects\The Escapists\TheEscapists_30_Nov_16.mfa`,
   буфер ключа обрезается по `strlen` после обнуления байт 128+.

2. **`te1_icons.py`** — разбирает exe → находит объект `Items` → строит карту
   ID→(анимация, направление, хендл картинки, PNG) и пишет `item_icon_map.json`.

3. **`item_icon_map.json`** — готовая карта: 281 слот (ID 0..278 = реальные предметы,
   + 2 запасных слота 279/280, у которых уже есть иконки в exe).

4. **`all_icons_sheet.png`**, **`icons_90_169.png`** — контактные листы для визуальной
   сверки (иконка совпадает с названием предмета).

## Как устроена иконка

Объект `Items` (handle **184**, есть дубли `Items_HUD` 210 и ещё пара 679/687 для
других фреймов) хранит иконки как **анимации × направления**:
- 16 «анимаций», непустые индексы: `0,1,2,5,6,7,8,9,10` (3 и 4 вырезаны разработчиком);
- каждая непустая анимация — до 32 «направлений», направление = 1 кадр = хендл картинки.

**ID предмета = порядковый номер слота**, если нумеровать непустые слоты подряд:
`анимация 0 (dir 0..31) → ID 0..31`, `анимация 1 → 32..63`, `анимация 2 → 64..95`,
`анимация 5 → 96..127`, `анимация 6 → 128..159`, `анимация 7 → 160..191`,
`анимация 8 → 192..223`, `анимация 9 → 224..255`, `анимация 10 → 256..280`.

Проверено: ID 0 = Cell Key (ключ), 5 = Sturdy Shovel (лопата), 25 = Crowbar (лом, handle 14),
55 = empty, 96 = Toothbrush (зубная щётка), 166 = Service Medal, 278 = Thruster (рыба/х3957).

## Зачем это нужно для «добавить свой предмет»

- **Маршрут A (занять ID)**: теперь можно *осознанно* выбрать, чью иконку взять — карта
  даёт иконку любого ID, включая вырезанные (11 Stun Rod, 78 Metalshop key и т.д.).
- **Маршрут C (своя иконка, байт-патч)**: известно точное место иконки в образе (handle).
  Остаётся подменить пиксели кадра «в тот же размер» (см. `MODDING_...` §6) — теперь это
  адресная задача, а не поиск вслепую.
- Слоты **279/280** уже имеют иконки в exe, но не имеют записи в `items_*.dat` — их можно
  попытаться оживить, добавив запись с ID 279/280 в `items_eng.dat`/`items_rus.dat`.
