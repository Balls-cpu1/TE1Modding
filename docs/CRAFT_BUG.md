# Почему свой предмет нельзя скрафтить — разбор и исправление

> Симптом: предмет добавлен в `items_rus.dat`, в игре он есть, рецепт в файле прописан,
> но при попытке скрафтить — «ничего не произошло».
>
> Причина найдена в байткоде событий (дамп `dumps/game_events.txt`). Их **две**, и обе
> надо чинить.

---

## Причина 1. Крафт-сканер перебирает только ID 0..199

Группа #431 (`офс 301560`) готовит список крафтового:

```
ЕСЛИ  начало уровня
ТО    craft_poss = ""
ТО    CraftNotes = "@"
ТО    активировать группу "craft_poss" 200 РАЗ      <-- вот оно
ТО    активировать группу "make_CraftNote_str" (CraftNotes)
```

Группа #432 на каждой итерации читает `Craft` у предмета с номером = счётчик итерации:

```
ЕСЛИ  группа "craft_poss" активна
ЕСЛИ  INI_ITEMS: Craft[счётчик] != ""
ТО    craft_poss += "@" + счётчик
```

Значит **предметы с ID ≥ 200 в список крафта не попадают вообще**.

Подтверждение на справочнике всех 279 предметов (`reference/te1_items_reference.json`):

| Счётчик | Лимит в игре | Максимальный ID, который его использует | Запас |
|---|---|---|---|
| `craft_poss` | **200** | **189** | 10 слотов |
| `ITEM_COUNT` | 261 | 260 (`Desk`) | 0 — впритык |

Ни одного крафтового предмета с ID ≥ 200 в оригинале нет — это не совпадение,
а ровно тот потолок, который задал разработчик.

**Побочный эффект `ITEM_COUNT=261`:** предметы с ID ≥ 261 также не попадают в
`DesksArray`/`PocketsArray`, то есть не спавнятся в тумбочках и у NPC.

## Причина 2. Настоящие рецепты захардкожены в байткоде по ID

Это главное. Поле `Craft=` в `.dat` используется **только для текста в журнале**
(группа #2858 собирает подсказку: `Name` + компоненты + требование интеллекта).

Реальное сопоставление делает группа #2908:

```
ЕСЛИ  группа "CraftSum" активна
ТО    создать CraftSort
ТО    CraftSort.добавить(c1)      ; предметы из трёх слотов крафта
ТО    CraftSort.добавить(c2)
ТО    CraftSort.добавить(c3)
ТО    CraftString = CraftSort[1] + "_" + CraftSort[2] + "_" + CraftSort[3]
```

`CraftSort` **сортирует** ID, пустой слот = `-1`. Дальше ~97 групп вида #2916
сравнивают строку с захардкоженным значением:

```
ЕСЛИ  CraftSum
ЕСЛИ  CraftString == "1_-1_53"
ТО    CraftString = ""
ТО    CraftOutput   = 71        ; Staff Key Mold
ТО    Craft_GiveBack = 1
ТО    активировать "Craft_Output" 1 раз
```

Извлечённая таблица (97 рецептов) — `work/recipes_hardcoded.json`. Примеры:

| CraftString | Результат | Компоненты |
|---|---|---|
| `1_-1_53` | 71 Staff Key Mold | Ключ персонала + Замазка |
| `-1_84_89` | 88 Plastic Entrance Key | Расплавленный пластик + Форма ключа входа |
| `13_4_95` | 128 Cushioned Inmate Outfit | Скотч + Роба + **Подушка** |
| `13_4_50` | 129 Padded Inmate Outfit | Скотч + Роба + Книга |

**Вывод:** новой строки `Craft=` недостаточно — в байткоде нет группы, которая
сопоставит твою комбинацию. Поэтому «ничего не произошло».

## Исправление (обе части делает `te1_mod.py`)

### 1. Снять потолок 200

Пункт меню **7. Фикс крафта**. Меняет в событиях одно 4-байтовое число:

```python
# уникальная иголка: действие «активировать craft_poss 200 раз» (58 байт)
needle = param(45, ev_str("craft_poss")) + param(22, ev_long(200))
events = events.replace(needle, needle_с_281, 1)
```

Иголка во всём файле встречается **ровно 1 раз** (свободный шаблон «long 200» —
19 раз, поэтому подменять нужно полную последовательность). Размер событий не
меняется, все 5473 группы после патча парсятся без остатка.

### 2. Добавить рецепт в байткод

Пункт меню **8. Свой рецепт**. Конструктор собирает группу, байт-в-байт повторяющую
структуру оригинальной #2916 (472 байта), и дописывает её в конец блока `ERev`:

```
ЕСЛИ  CraftSum
ЕСЛИ  CraftString == "13_4_95"
ТО    CraftString = ""
ТО    CraftOutput = 279
ТО    Craft_GiveBack = -1
ТО    активировать "Craft_Output" 1 раз
```

Проверено полным парсером: было 5473 группы → стало 5474, все читаются,
оригинальные не тронуты.

### Важно про порядок ID в рецепте

Игра **сортирует** три ID перед сравнением, поэтому в `CraftString` они всегда
по возрастанию, а пустые слоты (`-1`) оказываются в начале. Примеры оригинала:
`1_-1_53`, `-1_53_7`, `-1_-1_84`. Пиши комбинацию уже отсортированной.
