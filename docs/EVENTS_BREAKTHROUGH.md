# ПРОРЫВ: байткод событий расшифрован и ПАТЧИТСЯ (механики можно добавлять!)

> Дата: 2026-09-26. Это продолжение `docs/MECHANICS.md`, который заканчивался выводом
> «новая механика = правка байткода событий, но это отдельная большая реверс-задача».
> **Задача решена.** Теперь мы можем менять логику игры прямо в exe.

## Что сделано

1. **`tools/te1_frames.py`** — обходит поток чанков exe: 12 фреймов, имена, размеры.
   Фрейм `game` (основная тюрьма) содержит чанк Frame Events (13117):
   **2 420 852 байта** событий (совпадает с оценкой из MECHANICS.md).

2. **`tools/te1_events.py`** — ПОЛНЫЙ парсер формата событий Clickteam Fusion 2.5
   (runtime, build 288; порт из CTFAK2.0 `Events.cs` с нашими исправлениями).
   Формат (всё подтверждено на практике):

   ```
   "ER>>" i16 maxObjects i16 maxObjInfo i16 players i16[17] i16 qualifierCount {u16 objInfo i16 type}*
   "ERes" i32 размерБлокаГрупп
   "ERev" i32 размер { Группа }...        <- сами события
   "<<ER"

   Группа:   i16 size ОТРИЦАТЕЛЬНЫЙ (включая само поле!) u8 nCond u8 nAct u16 flags
             i16 line i32 isRestricted i32 restrictCpt {Условие}... {Действие}...
   Условие:  u16 size i16 objType i16 num u16 objInfo i16 objInfoList
             i8 flags i8 other u8 nParams u8 defType i16 identifier {Параметр}...
   Действие: u16 size i16 objType i16 num u16 objInfo i16 objInfoList
             i8 flags i8 other u8 nParams u8 defType {Параметр}...
   Параметр: u16 size(включая себя) i16 code {данные по code}
   Выражение: i16 objType i16 num u16 size {loader}; строка = UTF-16 + \0
   Терминатор списка выражений = 4 байта 00 00 00 00 (otype=0 + num=0)
   ```

   Нюансы, без которых ничего не собирается:
   - размер группы отрицательный и включает само поле размера;
   - размер условия/действия/параметра — положительный и тоже включает себя;
   - zlib = **level 9** (совпадает с оригиналом байт-в-байт);
   - строки сравнений — `cmp` в ExpressionParameter: **0 = «равно», 1 = «не равно»**;
   - чанк 13117 (flag=3) = `u32 распак.размер` + шифротекст(`u32 сжат.размер` + zlib);
   - поток чанков лежит **в оверлее PE** — exe можно свободно удлинять.

3. **`dumps/game_events.txt`** — все 5 473 групп событий фрейма `game` в читаемом виде
   (с именами объектов из банка). Это фактически **исходный код всей игровой логики**.

4. **`tools/te1_patch.py`** — патчер:
   - `identity` — пересборка exe без правок → **байт-в-байт идентичен оригиналу** (проверено
     для eur и rus сборок) — гарантия корректности каждого слоя;
   - `outfitdoor` — добавляет «дверь по форме» в указанную тюрьму: две новые группы
     (создание двери при загрузке карты + проверка формы при ходьбе), пересборка,
     шифрование, запись exe. Проверено парсером: оригинальные группы не тронуты.

## ГЛАВНОЕ ОТКРЫТИЕ: «дверь по форме» УЖЕ ЕСТЬ в PC-версии

В событиях фрейма `game` найдена полная реализация (MECHANICS.md ошибочно считал,
что она не разведена по тюрьмам):

- **Объект `Door - outfit` (handle 501)** ставится в DLC-тюрьмах группами
  `setup_DTAF`/`setup_SSS`/`setup_TOL`/`ww_setup` (действие `create`, координаты в байтах).
- **Проверка формы** — группы #1017–1020 (общая группа `move_check_doors`):

  | Тюрьма | Условие | Смысл |
  |---|---|---|
  | DTAF (Duct Tapes Are Forever) | `Outfit` содержит `228_` иначе блок | проходит только Henchman Outfit (228) |
  | TOL | `Outfit` содержит `3_` иначе блок | проходит только Guard Outfit (3) |
  | CCL | аналогично `3_` | то же |

- **Как работает движение**: группы `move_check` при коллизии ставят named-переменную
  `Blocked=1`; тогда `move_check_x/y` ОТКАТЫВАЮТ шаг (`act2/act3` — вернуть старую координату).
  `Blocked=0` → шаг применяется (привязка к сетке 16 px).
- **Текущая тюрьма** определяется **глобальной строкой №0** (для Center Perks = `perks`,
  также в коде встречаются `irongate`, `TOL`, `BC`, `CCL`, `DTAF`, `SS`).
- DLC-флаги (`DTAF=1` и т.п.) выставляются в группе `grab_map_data`/`map_vals` по имени карты.
- Базовые тюрьмы (Center Perks и др.) строятся из **внешних файлов `.map`**
  (группы `load_map_objects`, 169 шт.; переменные `Map_Name`, `Map_Routine`...),
  DLC — захардкожены в событиях.

Вывод: мобильная механика «дверь открывается только в форме X» собирается из готовых
кирпичей — мы клонируем DTAF-группы и меняем литерал формы и тюрьмы.

## Как пользоваться (пример: дверь медсестры в Center Perks)

```bash
# проверка целостности конвейера
python3 tools/te1_patch.py identity exe/TheEscapists_eur.exe.txt -o /tmp/id.exe.txt

# дверь, открывающаяся только в Infirmary Overalls (ID 38), на координатах (512,320)
python3 tools/te1_patch.py outfitdoor exe/TheEscapists_eur.exe.txt \
    --map perks --outfit 38 --x 512 --y 320 \
    -o work/perks_medicdoor.exe.txt
```

Потом переименовать `perks_medicdoor.exe.txt` → `TheEscapists.exe` (с бэкапом!) в папке игры.

Полезные ID форм: **3** Guard Outfit, **4** Inmate Overalls, **38** Infirmary Overalls,
**127** POW Outfit, **211** Soldier Outfit, **215** Bond Outfit (DTAF), **228** Henchman,
**238** Santa's Sweater, **239** Guard Elf.

## Ограничения / что дальше

- Координаты двери надо брать из `.map`-файла тюрьмы (сетка 16 px) — присылай файл карты.
- Идентификаторы условий в новых группах (-32000…) — заглушки; игра их, похоже, не
  проверяет, но при желании можно перенумеровать.
- Тем же способом можно: добавлять ЛЮБЫЕ объекты в любую тюрьму, менять стражу,
  делать новые проверки (ключ-карты, зоны), править крафт и т.д.
- Нужны ли двери-«пропускающие только без предмета в руках» — см. группу #1015
  (`Carrying >= 1` гейтит проверку дверей — как в DLC).
